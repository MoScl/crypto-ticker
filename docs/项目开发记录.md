## 0. 项目概述

CryptoTicker 是一款 **Windows / macOS 桌面端加密货币价格监控迷你悬浮窗**。

- **技术栈**：Electron `^30.1.0` + React `^18.3.1` + TypeScript + Vite 5 + electron-builder 24。
- **数据源**：Binance 优先 + CoinGecko 自动降级（统一 USDT 计价），经智能出口路由器（egress）选路；另含 okx / bybit / gate 等备用源。
- **核心交互**：迷你悬浮窗、**极简模式（minimalMode）** + **点击穿透（clickThrough，仅白名单可交互）**、自选币管理、系统托盘、开机自启、深色主题、**边缘缩放（EdgeResize）**。
- **打包**：Windows → NSIS 安装包；macOS → arm64 dmg + zip（universal 已废弃）。

> ⚠️ **重要说明**：本文档中「极简模式」「穿透白名单」「边缘缩放」「macOS 彩色托盘」等**核心功能均已在 `713d792` 提交并发布到 `v0.1.0`**；2026-09-10 的 `82c33f6` 是在此基础上的**状态显示与窗口行为微调**，二者共享同一套从 `713d792` 沉淀下来的设计约定（见 §0.2）。

# 第一部分：2026-08-21 ~ 08-22 会话（核心功能定型）

## 1. 项目初始化与数据源架构（08b3ff1）

**背景**：从零搭建一个常驻桌面、不抢焦点的加密货币价格悬浮窗。要求数据源高可用（主源挂了能自动降级）、网络在受限环境（代理 / 墙）下仍可用。

**关键决策与原因**：
- **Binance 优先 + CoinGecko 自动降级**：Binance 行情最全最快，但部分地区受限；CoinGecko 覆盖广、无地域限制，作为兜底。统一 USDT 计价避免跨币种换算混乱。
- **智能出口路由器（egress） + DNS-over-HTTPS（DoH）**：在主进程 `src/main/net/` 下自建出口层，绕开系统被污染/不通的 DNS，保证 `api.binance.com` / `api.coingecko.com` 可达。
- **上下文隔离（contextIsolation）+ preload 桥接**：`src/main/preload.ts` 只暴露白名单 API 到 `window.api`，主进程 IPC 处理所有系统调用，避免渲染层直接触达 Node。
- **穿透逃生按钮（ClickThroughEscape）**：`08b3ff1` 已内置"退出穿透"机制——穿透开启时右上角保留一个始终可交互的逃生按钮，避免用户被锁死在穿透态。
- **系统托盘常驻**：`src/main/tray.ts` 加载 `assets/` 下的托盘图标，点击托盘可恢复窗口 / 打开设置。

**文件改动（初始提交，73 文件）**：
- `src/main/data/`：`binance.ts` / `coingecko.ts` / `dataSource.ts`（智能选路）/ `ranking.ts` / `trending.ts` + `sources/okx|bybit|gate.ts`
- `src/main/net/`：`doh.ts` / `egress.ts` / `rawRequest.ts` / `systemProxy.ts` / `logger.ts`
- `src/main/`：`config.ts` / `http.ts` / `network.ts` / `index.ts` / `tray.ts` / `windows.ts` / `preload.ts`
- `src/renderer/`：完整 React 应用（`App.tsx` / `MiniWindow.tsx` / `AddCoinModal.tsx` / `CoinRow.tsx` / `SettingsPanel.tsx` / `ClickThroughEscape.tsx` / `NetworkIndicator.tsx` / `RefreshTime.tsx` / `store/useAppStore.ts` / `i18n/{zh,en}.ts` / `styles/global.css`）
- `src/shared/`：`types.ts` / `constants.ts`

**结论**：初版即具备生产可用骨架；后续所有功能（极简/穿透白名单/边缘缩放/彩色托盘）都建立在此骨架之上。

## 2. 应用图标与标题栏 Logo 重做（529ea14 / bc34167）

> 这一阶段经历了"先用几何近似 → 用户不满 → 真实字体渲染 → 多变体对比 → 选定变体 C → 全项目统一 → exe 图标注入"的完整迭代。

### 2.1 设计目标与最终定稿（变体 C）

**背景**：标题栏需要一枚与界面风格一致的 Bitcoin 徽章 Logo；用户最初对复杂 ₿ 徽章不满意（"感觉 logo 不对劲"），给出参考稿并明确要求**先渲染效果确认再动手**。

**最终定稿（变体 C，用户在 4 个候选中选定）**：
- 金色平底圆底色 `#F6B73C`（界面主色）
- 亮金描边 `#FFD98A`（1.5px）
- 深色 "B" 字形（Arial 700，26px）+ **碗内双竖线**（rect，坐标 `16.8/25, y13, 2.6×19`，色 `#1a1a1a`）

**决策与原因**：
- 用户从 4 个 ₿ 变体（A 两侧贯穿竖线 / B Unicode ₿ 字符 / C 参考稿碗内竖线 / D 纯矢量手绘）中选定 **C**——碗部为**描边式空心**（碗缘 + 双竖线），而非实心块。
- **被否决**：①几何近似拼字（`make-icon.mjs` 的方块近似）→ 方块感、与标题栏圆润 Arial 字体不一致；②初次把 B 画成**实心块**（碗部填实）→ 32px ASCII 预览糊成一整块，16px 更不可辨。
- **踩坑**：flex `align-items:center` ≠ 视觉居中（见 §2.3）；Electron 测量脚本必须用 CommonJS（`.cjs` + `require`），不能 `.cjs` + `import`。

### 2.2 图标生成器：真实字体渲染（make-icon-electron.cjs）

**背景**：`scripts/make-icon.mjs` 用矩形几何近似拼 B 字（方块感），与标题栏 Arial 字体圆润的 B 不一致。

**决策**：新建 `scripts/make-icon-electron.cjs`，用 **Electron `BrowserWindow`（offscreen）+ `capturePage()`** 以真实 Chromium 字体渲染引擎逐尺寸渲染 SVG，再组装 ICO + PNG。这样图标字形与标题栏**完全同源**。

**关键实现要点（踩坑沉淀）**：
- 主进程脚本**必须 CommonJS**（`require`），不能 `import`（否则报 "App threw an error during load"）。
- offscreen 窗口需 `setContentSize + loadURL + 延时后 capturePage`；`scaleFactor` 非 1 时用 `img.resize` 校准。
- 输出：`icon.ico`（16/24/32/48/64/128/256 @32bpp）、`icon.png`（1024）、`icon-512.png`（512）、Windows 托盘 `tray-icon.png`(32)+`@2x`(64)、macOS 托盘 `tray-mac.png`(16)+`@2x`(32)。

**配套验证工具** `scripts/verify-icon.cjs`：PNG 解码 + 三色像素统计 + 32px ASCII 预览，可复用于后续图标改动核验。

### 2.3 标题栏 Logo 垂直对齐修正（translateY(2px)）

**背景**：logo（₿ 金色徽章 SVG，13→16px）与 "Crypto" 文字未真正垂直居中，logo 明显偏高。

**根因（实测）**：`.title` 用 flex `align-items:center` 只对齐了行盒几何中心，而文字字形的**墨迹中心**（Segoe UI 度量 ascent 9px / descent 3px，行盒 16px）比行盒中心低 2px，SVG 因此视觉偏高。写临时测量脚本在真实渲染环境实测：文字墨迹中心 17px vs logo 中心 15px，**偏差恰好 2px**。

**修复**：`global.css` `.title-logo` 加 `transform: translateY(2px)`（不改尺寸/布局/间距，纯视觉补偿）。

```css
.title-logo { transform: translateY(2px); }  /* flex 居中 ≠ 视觉居中，字体度量补偿 */
```

> **方法论（可复用）**：flex 居中 ≠ 视觉居中，字体度量导致的偏差要用 `canvas.measureText` 的 `actualBoundingBoxAscent/Descent` + 基线探针实测再补偿。Electron 测量需 `env -u ELECTRON_RUN_AS_NODE` + `app.disableHardwareAcceleration()`，否则 `require('electron')` 返回路径字符串 / GPU 进程崩溃。

### 2.4 exe 内嵌图标修复（rcedit 手动注入）

**根因**：electron-builder 的 `signAndEditExecutable` 因沙箱 `winCodeSign` 解压失败被跳过 → exe 一直是 Electron 默认图标（这是用户感觉"很多地方旧 logo"的真正来源）。

**最终方案（沙箱环境可落地）**：恢复 `signAndEditExecutable:false` 打包，再用缓存中现成的 `rcedit-x64.exe`（各 `winCodeSign/<hash>/` 目录内都有）手动注入：

```bash
"C:\...\winCodeSign\568105607\rcedit-x64.exe" "release/win-unpacked/CryptoTicker.exe" --set-icon "assets/icon.ico"
```

> **可复用经验**：沙箱内给 Windows exe 换图标 = electron-builder 打包后用缓存 `rcedit-x64.exe` 手动注入，无需 `signAndEditExecutable`。

## 3. 极简模式（minimalMode）功能（713d792）

**背景**：用户需要一种"只留行情、隐藏一切操作元素"的专注视图。

**决策与原因**：
- **配置驱动**：`shared/types.ts` 的 `AppConfig` 加 `minimalMode: boolean`（默认 `false`），走 electron-store 合并持久化，重启恢复。
- **纯渲染层实现**：极简模式不碰主进程（极简态仍复用现有穿透轮询 IPC），主进程零改动。
- **逃生入口下沉**：极简模式隐藏标题栏与搜索条后，穿透解锁 / 退出极简入口改为**底部状态栏右侧纯图标按钮**（`StatusbarActions.tsx`），复用已有穿透逃生机制（上报按钮矩形 + 订阅高亮态）。

**演进（关键决策轨迹）**：
1. 初版用独立底部控制条 `MinimalBar.tsx`（设置 + 解锁穿透）。
2. 用户改用纯图标并入状态栏右侧 → `MinimalBar` 删除，新增 `StatusbarActions.tsx`（锁图标=解锁穿透，展开图标=退出极简）。
3. 极简模式下 `ClickThroughEscape`（右上角逃生按钮）**条件不渲染**（`{!minimalMode && ...}`）——否则标题栏 CSS 隐藏但其上报的 0 高 rect 会与状态栏按钮上报竞态覆盖。

## 4. 穿透交互白名单 + 全局去 hover（713d792）

**背景**：点击穿透开启期间，只有"解锁穿透 / 退出极简"两个按钮需要可点，其余 UI 应完全穿透到下层应用；且穿透态下不应有任何 hover / 手型光标误导用户"这东西能点"。

**决策与原因（双层双保险）**：
1. **主进程**：常态穿透 `setIgnoreMouseEvents(true, {forward:false})`。
   - **关键**：原 `{forward:true}` 会把 mousemove 转发给渲染层 → 渲染层出现 `:hover` / 手型光标，但点击仍穿透，造成"看起来能点实际已穿透"的误导。**改 `forward:false` 后渲染层完全收不到鼠标事件，无 hover、光标保持系统默认**。命中白名单按钮区时仍临时 `setIgnoreMouseEvents(false)` + `focus` + 广播恢复交互。
2. **渲染层**：`app` 根加 `ct-active` 类（clickThrough），CSS 全局禁用非白名单元素：
   ```css
   .app.ct-active * { pointer-events: none !important; cursor: default !important; }
   .app.ct-active .ct-hot, .app.ct-active .ct-hot * { pointer-events: auto; cursor: pointer; }
   ```
   即使命中按钮区恢复整窗交互，非白名单元素也不可点（事件被窗口吞但鼠标在按钮上点不到别处）。
3. **白名单控件加 `ct-hot`**：`StatusbarActions` 两按钮 + `ClickThroughEscape`。
4. **状态同步**：解除穿透 → `applyClickThroughWindow(false)` 停轮询 / 清 `ctBtnRect` / `ctHold` / 广播 false → `ct-active` 移除 → hover/点击完整恢复，无事件残留。

**变更摘要**：
- `src/main/index.ts`：`startHoverDetector` 用 `forward:false`；`setIgnoreMouseEvents` 行为调整。
- `src/renderer/components/StatusbarActions.tsx` / `ClickThroughEscape.tsx`：加 `ct-hot` class。
- `src/renderer/styles/global.css`：新增 `.app.ct-active` 规则。
- 产物验证：`ct-hot`×3 / `ct-active`×1 / 主进程 `forward:false`。

**结论**：穿透"仅白名单可点" = 主进程 `forward:false`（无 hover）+ 渲染层 `ct-active` 全局 `pointer-events` 禁用 + `ct-hot` 例外，双保险；白名单外无任何交互反馈（hover 与可点击同步消失）。

## 6. 穿透态按钮"退出极简不能点击"——屏幕坐标修复

**背景**：穿透态下点"退出极简"按钮偶发点不到，白名单机制形同虚设。

**根因（精修方案前假设）**：主进程判定用 `getBounds() + 相对 rect`——**无边框透明窗口的 DWM 阴影 / DPI 导致判定区域与用户视觉位置偏移** → 点击 miss → 穿透。

**修复（已端到端验证）**：
1. `StatusbarActions.tsx` + `ClickThroughEscape.tsx` 上报按钮**屏幕绝对坐标**：
   ```ts
   const r = el.getBoundingClientRect();
   api.setClickThroughBtnRect({
     x: window.screenX + r.x,   // 屏幕坐标系，与主进程同 DIP，零偏移
     y: window.screenY + r.y,
     w: r.width, h: r.height,
   });
   ```
2. 穿透开启时**每 300ms 定时重报**（覆盖窗口移动/缩放/布局变化）。
3. `main/index.ts` `startHoverDetector` **去掉 `getBounds` 换算**，`screen.getCursorScreenPoint()` 直接比对：
   ```ts
   const cursor = screen.getCursorScreenPoint();
   const hit =
     cursor.x >= ctBtnRect.x - CT_BTN_MARGIN &&
     cursor.x <= ctBtnRect.x + ctBtnRect.w + CT_BTN_MARGIN &&
     cursor.y >= ctBtnRect.y - CT_BTN_MARGIN &&
     cursor.y <= ctBtnRect.y + ctBtnRect.h + CT_BTN_MARGIN;
   if (hit) ctLastHitAt = Date.now();
   const interactive = ctHold || hit || Date.now() - ctLastHitAt < CT_HIT_GRACE_MS;
   ```
   - `CT_BTN_MARGIN = 12`（小按钮 + 边缘抖动容差）
   - `CT_HIT_GRACE_MS = 600`（命中后点击保护：覆盖用户从光标进入按钮到 mousedown 的反应时间）
   - `HOVER_POLL_MS = 60`

**验证**：
- typecheck 0 错误、双进程构建成功。
- 产物确认：`screenX`×5（两组件上报）、`setInterval`×2、`cursor.x >= ctBtnRect.x`（屏幕直比）；`getBounds` 仅剩边缘 resize 一处用途。
- **端到端真实测试**（系统级鼠标 `mousectl.py`）：极简 + 穿透 → 点 exit (241,12) → `minimalMode` true→false ✅；测试后恢复用户配置。

**结论**：穿透按钮判定必须用渲染层屏幕坐标（与视觉一致），`getBounds` 换算在无边框透明窗口不可靠。

## 10. Windows 安装图标修复

**背景**：安装后桌面 / 开始菜单快捷方式显示系统默认图标，需替换为应用自定义图标。

**根因（已实证）**：快捷方式图标不是独立配置，它就是 app exe 的图标（`app-builder-lib/templates/nsis/include/installer.nsh` 中 `CreateShortCut ... "$appExe" 0`，IconFile 直接指向 exe）。而 `WinPackager.signApp()` 里 `if (signAndEditExecutable === false) return false;` 会让 **rcedit 整段跳过**——图标 + 版本信息都不注入 exe。原 `electron-builder.yml` 恰好有 `signAndEditExecutable: false`，放进去的 exe 是 Electron 默认图标。实证：`release/win-unpacked/CryptoTicker.exe` 内搜不到 UTF-16 `CryptoTicker`（版本信息没注入），但能搜到 `icon.ico` 多帧 → 说明安装包里的 exe 未注入图标。

- 删 `signAndEditExecutable:false`：**安全**。Windows 上 rcedit 走 `app-builder` 自带实现，不下载 winCodeSign；无证书时 `sign()` 也会提前 return。原"winCodeSign 解压失败"顾虑在这条路径不成立。
- 新增 `build/installer.nsh` 作**双保险**：用随包安装的独立 `app.ico` 重建桌面 + 开始菜单快捷方式图标，并 `SHChangeNotify` 刷新图标缓存。
- `electron-builder.yml` 补 `installerIcon` / `uninstallerIcon`（否则安装/卸载程序图标不继承 `win.icon`）。

**文件改动**：

`electron-builder.yml`（win 段）
```diff
 win:
   target: nsis
   icon: assets/icon.ico
-  # 沙箱环境无 darwin 符号链接创建权限，winCodeSign 解压失败，跳过 rcedit
-  signAndEditExecutable: false
+  # 不要设 signAndEditExecutable:false —— 否则 rcedit 整段跳过，exe 保留 Electron 默认图标
```

`electron-builder.yml`（新增 extraResources + nsis 段）
```yaml
extraResources:
  - from: assets/icon.ico
    to: app.ico          # 安装到 <安装目录>\resources\app.ico，供 installer.nsh 兜底

nsis:
  oneClick: false
  perMachine: false
  allowToChangeInstallationDirectory: true
  createDesktopShortcut: true
  createStartMenuShortcut: true
  shortcutName: CryptoTicker
  installerIcon: assets/icon.ico
  uninstallerIcon: assets/icon.ico
  include: build/installer.nsh
```

`build/installer.nsh`（新增，核心片段）
```nsis
; customInstall 位于内置 addStartMenuLink / addDesktopLink 之后，可覆盖其创建的快捷方式
!macro customInstall
  ${if} ${FileExists} "$newDesktopLink"
    ShellLink::SetIcon "$newDesktopLink" "$INSTDIR\resources\app.ico" 0
  ${endIf}
  ${if} ${FileExists} "$newStartMenuLink"
    ShellLink::SetIcon "$newStartMenuLink" "$INSTDIR\resources\app.ico" 0
  ${endIf}
  ShellLink::SetLnkAUMI "$newDesktopLink" "${APP_ID}"
  ShellLink::SetLnkAUMI "$newStartMenuLink" "${APP_ID}"
  System::Call 'shell32::SHChangeNotify(i 0x8000000, i 0, i0, i0)'
!macroend
```

**图标文件现状（无需更换）**：`assets/icon.ico` 已是多尺寸 `16/24/32/48/64/128/256 @32bpp`，Windows 够用（缺 20/40/96 会缩放取邻帧，视觉无影响）。

**结论**：删 `signAndEditExecutable:false` + 新增 `installer.nsh` 双保险，安装后快捷方式图标即应用自定义图标。`npm run typecheck` + YAML 解析通过。**本会话未实际打包验证**（遵循"打包需确认"约定）。

## 14. 「等待数据…」收敛为仅首次启动显示

**背景**：用户反馈"收到过数据还是会显示等待数据…"。

**根因排查**：`commonWaiting` 有 5 处引用，其中 4 处看的是 `sourceStatus`（数据源状态）而非"有没有数据"；状态栏右侧却显示「连接中…」——同一状态三处说法。更深层根因在 store 时间戳（见下）。

**决策**：
1. 网络详情弹层 / 设置面板的「数据源」行：`!sourceStatus` 时的 `commonWaiting` → `mainSrcStateConnecting`（连接中…），与状态栏一致。
2. "有数据"判据改为 **tickers 本身**（而非单一时间戳），并堵住时间戳失效口子。

**文件改动**：

`NetworkIndicator.tsx` 与 `SettingsPanel.tsx`（`!sourceStatus` 两处）
```diff
  const srcText = !sourceStatus
-   ? t('commonWaiting')
+   ? t('mainSrcStateConnecting')
    : t('netSrcText', { label: srcName, state: srcStateName });
```

`src/renderer/store/useAppStore.ts`（时间戳兜底——原写法 `Math.max(s.lastUpdateTs, t.ts)` 在 `t.ts` 缺失时得 NaN，`NaN > 0` 恒 false → 价格显示但判定失败，永久"等待"）
```ts
function tickerTs(t: Ticker): number {
  return typeof t.ts === 'number' && Number.isFinite(t.ts) && t.ts > 0 ? t.ts : Date.now();
}
// applyTicker / applySnapshot 改用 tickerTs(t)
```

`RefreshTime.tsx`（判据换成 tickers）
```ts
const hasTickers = useAppStore((s) => Object.keys(s.tickers).length > 0);
const hasData = hasTickers || lastUpdateTs > 0;
// elapsed<0 时：有数据按「刚刚」，无数据才「等待数据…」
```

**现在的行为**：

| 场景 | 状态栏 | 弹层/设置「数据源」 |
|---|---|---|
| 首次启动、未收到数据 | 等待数据… | 连接中… |
| 收到过数据（断网/降级/重连） | 30秒前 / 5分钟前 / 2小时前 | 正常 / 降级 / 异常 |
| 有行情但时间戳异常 | 刚刚（兜底） | 连接中… |

**结论**：`typecheck` + `build:renderer` 通过；`commonWaiting` 全仓只剩状态栏与网络详情「数据刷新」两处，均由 `hasTickers` 门控。

**需用户确认点（当时回问未获答）**：看到「等待数据…」时价格是有数字还是「—」？有数字 → 本版已覆盖；是「—」 → 说明渲染层根本没收到行情（主进程订阅链路问题，与文案逻辑无关）。后续以此版为准实现。

## 16. 极简模式窗口宽度联动（160 / 240）

**背景**：进入极简模式窗口宽度 160，退出极简 240。

**决策**：逻辑放**主进程**统一处理——极简模式有 3 个入口（标题栏按钮、设置面板开关、状态栏「退出极简」），三者都走 `patchConfig → api.saveConfig → IPC.SAVE_CONFIG`，在主进程一个拦截点全覆盖。锚定右边缘（悬浮窗多贴右侧）、用 `workArea` 夹回屏幕可用区（多显示器可正确取窗口所在屏）、只改宽度。

**文件改动**：

`src/shared/constants.ts`
```ts
export const MINIMAL_WINDOW_WIDTH = 160;
export const NORMAL_WINDOW_WIDTH = 240;
// 两值都必须 >= windows.ts 的 minWidth(160)
```

`src/main/index.ts`
```ts
function applyMinimalWindowWidth(minimal: boolean): void {
  const win = mainWindow;
  if (!win) return;
  const b = win.getBounds();
  const w = minimal ? MINIMAL_WINDOW_WIDTH : NORMAL_WINDOW_WIDTH;
  if (b.width === w) return;
  let x = b.x + b.width - w;                       // 右边缘固定
  const area = screen.getDisplayMatching(b).workArea;
  if (x < area.x) x = area.x;
  if (x + w > area.x + area.width) x = Math.max(area.x, area.x + area.width - w);
  win.setBounds({ x, y: b.y, width: w, height: b.height }, true);
  appConfig.windowBounds = { x, y: b.y, w, h: b.height };
  saveConfig(appConfig);
}
// SAVE_CONFIG handler 内比对 prevMinimal，仅 minimalMode 变化时触发
```

**有意没做**：启动时不强制按 minimalMode 套宽度（保留手动拖宽后的尺寸）。如需"极简恒等于 160"，在 `createMiniWindow()` 后调一次 `applyMinimalWindowWidth(appConfig.minimalMode)`。

**结论**：`typecheck` 通过；`npm run build:main` 重新编译，产物含新函数。

## 17. 启动默认状态复位（极简 + 穿透）

**背景**：启动时应为默认模式；若是极简则退出极简。后续追加：穿透也默认 false。

**决策**：在 `app.whenReady()` 建窗后，`appConfig.minimalMode` / `appConfig.clickThrough` 任一为真则复位为 false 并立即 `saveConfig` 落盘（本次与下次启动都是默认态）。**穿透复位必须放在 `applyClickThroughWindow` 之前**，否则窗口会先进穿透态（`setIgnoreMouseEvents(true)` + 启动光标探测定时器），中间一瞬鼠标点不到窗口且多启停一次探测。

**文件改动**：

`src/main/index.ts`（建窗后）
```ts
mainWindow = createMiniWindow();
mainWindow.setOpacity(appConfig.opacity);
mainWindow.setAlwaysOnTop(appConfig.alwaysOnTop);

// 启动策略：始终以默认状态启动（非极简 + 非点击穿透）
const resetMinimal = appConfig.minimalMode;
const resetClickThrough = appConfig.clickThrough;
if (resetMinimal || resetClickThrough) {
  appConfig.minimalMode = false;
  appConfig.clickThrough = false;
  saveConfig(appConfig);
}
applyClickThroughWindow(appConfig.clickThrough);   // 复位后才应用
if (resetMinimal) applyMinimalWindowWidth(false);  // 极简复位同步宽度到 240
```

**结论**：`typecheck` + `build:main` 通过。启动默认态 = 非极简 + 非穿透 + 宽 240，且复位立即落盘。托盘在复位之后创建，`getClickThrough` 读到已是 false，无需额外 `trayRefresh()`。

## 18. 打包体积优化

**背景**：mac / Windows 打包后包很大，要求优化。

**根因分析**：大头是 Electron 运行时本身（约 169MB）动不了。能省的都在边上。实测构成（as of 2026-09-10）：
- `release/win-unpacked/locales/`：55 个语言包共 37.4MB
- `app.asar` 内 `node_modules` 7.26MB，其中 react-dom 的 development/profiling/server 全量构建占 5.5MB（渲染层早已被 Vite 打进 `dist/renderer/assets/*.js`，主进程不需要）
- `LICENSES.chromium.html` 9.8MB + `LICENSE.electron.txt` ≈ 10MB
- SwiftShader 软件渲染库（vk_swiftshader 等）≈ 13MB

**已落地改动**：

`electron-builder.yml`
```yaml
electronLanguages:        # 只保留中英文（UI 自绘，只需 zh-CN + en-US）
  - zh-CN
  - en-US
compression: maximum     # 安装包 LZMA 极限压缩
afterPack: build/afterPack.cjs
npmRebuild: false        # 运行时依赖纯 JS 无 native 模块，跳过 rebuild 仅提速
# 另：react / react-dom / zustand 移到 devDependencies（见 package.json）
```

`package.json`
```json
"dependencies": { "electron-store": "^8.2.0", "https-proxy-agent": "^5.0.1", "ws": "^8.21.3" },
"devDependencies": { ... "react": "^18.3.1", "react-dom": "^18.3.1", "zustand": "^4.5.4" ... }
```
> ⚠️ 注释固化在 yml 内：不要把这三个包挪回 dependencies，否则 asar 立刻涨回 7.6MB。

`build/afterPack.cjs`（新增，两个开关当前均为 `true`）
```js
const STRIP_LICENSES = true;      // 删 LICENSES.chromium.html + LICENSE.electron.txt
const STRIP_SWIFTSHADER = true;   // 删 SwiftShader（vk_swiftshader / libEGL / libGLESv2）
```
macOS 路径必须带 `Versions/A`（Frameworks/Libraries 只是指向它的符号链接，删链接删不掉真实文件）。

`src/main/index.ts`（删 SwiftShader 必须配套禁用硬件加速）
```ts
// 删 SwiftShader 后 Chromium 失去"无 GPU 回退软件渲染"能力，主动禁用硬件加速
// 让所有环境统一走 CPU 合成，避免无 GPU 环境（虚拟机/远程桌面/云桌面）黑屏或崩溃
app.disableHardwareAcceleration();
```

**mac 架构**：`mac.target` dmg + zip 的 arch 从 `universal` → `arm64`（放弃 Intel Mac，体积约减半）。

**预期结果**：
- Windows 安装包：78MB → 约 62–66MB；安装后磁盘：263MB → 约 190MB
- macOS dmg（arm64 单架构）：约为原 universal dmg 的一半

**被否决 / 未采纳的方案**：
- **换 Node 版本**：本机 Node 只跑 vite/tsc，不进产物（app 内是 Electron 内置 Node 18.20），对体积零影响。
- **升级 / 降级 Electron**：升级只会更大（Chromium 逐版本变大）；降级 22.x 省 10–20MB 但丢安全更新，不划算。
- **small-icu 自行编译 Electron**：把 `icudtl.dat` 11MB→2MB，需自建编译环境，成本极高。
- **换 Tauri**：见 §19。

**仍可做的（收益递减，未做）**：
| 选项 | 收益 | 风险 |
|---|---|---|
| `electron-store` 换手写 JSON（`app.getPath('userData')`+fs，ajv 校验器占大头） | 1–1.5MB | 改约 30 行，低风险 |
| mac dmg `format: UDBZ` | 再小 5–10%（约 3–5MB） | 挂载稍慢，macOS 11+ 兼容 OK |

**结论**：`node --check` + `typecheck` + `build:main` 通过，YAML 解析确认各项生效。**本会话未实际打包验证**（含删除文件行为，建议实测一次确认删 SwiftShader + 禁用硬件加速后窗口正常）。

## 19. Tauri 迁移评估（被否决）

**背景**：用户问换 Tauri 是否可靠、值得折腾。

**结论**：**Tauri v2（2.11.x）本身成熟可靠**（Spacedrive / AppFlowy / Clash Verge / GitButler 在用），但**对本项目现在不值得**——最值钱的功能恰好撞在 Tauri 最薄弱的三点：

| 现用 Electron 能力 | Tauri v2 现状 | 成本 |
|---|---|---|
| ipcMain / webContents.send | invoke + events | 低 |
| 开机自启 / 全局快捷键 / 自动更新 / store / openExternal | 各对应插件 | 低 |
| **点击穿透 setIgnoreMouseEvents** | 无 per-region hit test，需 Rust 循环轮询光标 + `set_ignore_cursor_events` | **高** |
| **透明无边框 + 置顶 + 边缘缩放** | 有但 Windows 走分层窗口、macOS 需 `macOSPrivateApi:true`（无缘 Mac App Store） | **高，须实测** |
| **托盘动态绘制图标**（金色徽章/彩色矩形） | 有 set_icon，但需 Rust 侧手写绘制 + 每次刷新重建 | **高，最大重写项** |
| session.setProxy / ws 长连接 / net.* | reqwest / tokio-tungstenite / 或前端 WebSocket（但代理丢失） | 中 |

**收益真实数字**：Windows 安装包 66MB → 5–8MB；macOS dmg 70MB → 4–6MB；常驻内存 200–350MB → 60–120MB。
⚠️ **陷阱**：Windows 体积是"转移"不是"消失"——Tauri 依赖系统 WebView2，Win11 自带、Win10 不一定，缺了引导下载约 130MB。

**值得迁移的条件**：要做移动端（Tauri v2 一套代码五端）、或大版本重写、或用户明确抱怨内存。
**关注**：Tauri 3 的 CEF 后端（`cli-cef` alpha）走"轻壳 + 固定 Chromium"中间路线，GA 后才是更稳的迁移时机。

**建议**：别直接迁移，先花 1 天 spike 验证三件事（Windows+macOS 各跑）：透明置顶+边缘缩放、穿透白名单命中、托盘图标动态刷新性能；任一不过就放弃。

# 汇总

## 20. 踩坑经验汇总（全量）

1. **穿透判定必须用屏幕坐标**：无边框透明窗口下 `getBounds()+相对rect` 受 DWM 阴影 / DPI 偏移影响，判定区域与视觉不符；改渲染层上报 `window.screenX/Y + rect`，主进程 `getCursorScreenPoint()` 直比（§6）。
2. **`setIgnoreMouseEvents(true,{forward:true})` 会误导**：转发 mousemove → 渲染层出现 `:hover`/手型但点击穿透。改 `forward:false` + 渲染层 `ct-active` 全局 `pointer-events:none` 双保险（§4）。
3. **`Math.max(s.lastUpdateTs, t.ts)` 在 `t.ts` 缺失时得 NaN** → `NaN > 0` 恒 false，"等待数据"永久挂着。判据应优先看 tickers 非空，并对 `ts` 做 `Date.now()` 兜底（§14）。
4. **`signAndEditExecutable:false` 让 rcedit 整段跳过** → exe 无图标无版本信息，NSIS 快捷方式（IconFile 指向 exe）显示系统默认图标。删之即可，Windows 上 rcedit 不依赖 winCodeSign（§10）。
5. **NSIS 快捷方式图标 = exe 图标**，必须保证 exe 注入自定义图标（或用 `installer.nsh` 双保险用独立 ico 重建）（§10）。
6. **AUMID 三处必须一致**（yml `appId` / `setAppUserModelId` / `SetLnkAUMI`），否则任务栏分组串到其他 Electron 应用（§11）。
7. **Electron `skipTaskbar` 在 hide→show 后可能"长回"任务栏** → 每次 `window 'show'` 事件重新 `setSkipTaskbar(true)`（§11）。
8. **删 SwiftShader 必须配套 `app.disableHardwareAcceleration()`**，否则无 GPU 环境黑屏/崩溃（§18）。
9. **mac 路径 `Frameworks/.../Libraries` 是符号链接**，删链接删不掉真实文件，必须写 `Versions/A/Libraries/...` 完整路径（§18）。
10. **`npm run make-icon` 会覆盖高质量图标为低细节版** → 禁止运行，已提交的是 `make-icon-electron.cjs` 产物（§0.2/§2）。
11. **改主进程后必须 `npm run build:main`**（dist 在 gitignore 内），否则直接跑 dist 不生效（§0.2）。
12. **`display:none` vs `visibility:hidden`**：要"不占宽度且不产生 flex gap"时必须用前者（极简隐藏箭头/文本均用此，§12/§15）。
13. **i18n 类型 `Dict = typeof zh` + `Record<AppLanguage, Dict>`** 是强约束——zh/en 改单边 tsc 直接报错，能挡住漏改（§13）。
14. **git CRLF 警告**：提交用 `git -c core.safecrlf=false commit` 规避（§0.2）。
15. **推送用系统 Git**（`C:\Program Files\Git\cmd\git.exe`），勿用沙箱 PortableGit（credential-manager 段错误）（§0.2/§8）。
16. **flex 居中 ≠ 视觉居中**：字体度量导致偏差用 `canvas TextMetrics` + 基线探针实测补偿（§2.3）。
17. **沙箱 trash 拦截 `dist/` 清理**：手动 `rm -rf dist/renderer`（safe-delete git hooks 干扰）（§0.2/§8）。
18. **Electron 主进程脚本必须 CommonJS**（`.cjs` + `require`），不能 `import`（§2.2）。
19. **exe 换图标（沙箱）**：electron-builder 打包后用缓存 `rcedit-x64.exe` 手动 `--set-icon` 注入（§2.4）。
